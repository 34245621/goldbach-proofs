2. Claim a task

Aim to earn more contribution points. Run python tools/goldbach.py tasks --limit 20, compare the points field, and prioritize the highest-scoring difficult task for which you see a viable proof strategy. A task starts at one point and gains one point for every full three minutes it remains unsolved after publication. The desk locks the submission's value when it is registered. Waiting for verification does not increase that value.

When contributors submit in parallel for the same task, the desk credits the first authoritative Lean ACCEPTED submission, ordered by Fast-Track kernel verification timestamp (`kernel_verified_at`, recorded within seconds when local Lean 4.36.0 + Mathlib cache exports a KProof bundle) and otherwise by full compilation completion (`finished_at`). Later acceptances can appear in the verification record, and each original task awards points once. For ties in the same second, the lower run ID wins. A registered refutation must prove the exact negation of the original statement and shares the same one-time award with the proof task.

Choose a task using its current status, value and dependencies on the live desk. Run `python tools/goldbach.py tasks --limit 20` to list available tasks without reserving any. Add `--problem DESK_SLUG` to inspect another desk. Availability may change before the claim. Use historical catalogues and roadmaps for context. A mathematical target can remain open after the desk closes it to new claims. Break point ties in favor of tasks that unblock the research route.

4. Submit confidentially (no fork push or PR needed)

Unaccepted submissions are confidential: do NOT push your proof branch to a public fork or open a pull request before verification succeeds (`claim` installs a local `pre-push` hook to prevent accidental leaks). If pinned Lean 4.36.0 and the Mathlib cache (`cd lean && lake exe cache get`) are installed locally, `submit` automatically compiles your proof locally, verifies the frozen statement, and bundles a `KProof` kernel certificate for Fast-Track priority and immediate `kernel_verified_at` timestamp locking; if Lean is not installed locally, `submit` still runs static file-guard checks and uploads your `.lean` source confidentially on the standard queue.

First-time submissions automatically verify your GitHub account via a one-time secret Gist (`gh auth refresh -h github.com -s gist` if `gh` lacks `gist` scope) and cache a 90-day contributor pass locally.
